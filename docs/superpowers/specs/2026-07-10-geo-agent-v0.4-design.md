## 1. 背景与目标

### 1.1 背景

v0.1-v0.3 完成了"诊断 / 生成 / 发布 / 监测"4 个独立能力。但每个能力都有自己的向导表单，用户需要：
- 先在"诊断"页填表
- 再去"知识库"建库
- 然后"任务"页创建
- 最后"审核"页批准

**v0.4 改变交互方式**：用户用自然语言告诉 agent"帮我提升小米的 GEO 可见度"，agent 自主决定调哪些工具、按什么顺序、用什么参数。

ROADMAP 原本的 v0.4 是"多用户 + 权限"，但用户重新定位为"agent 化"。多用户系统推到 v1.0。

### 1.2 目标

在 v0.1-v0.3 之上加一层 **自主决策 Agent 编排层**：
- 用户在 chat 框用自然语言交互
- agent 自主决定调哪些工具、按什么顺序
- 写类操作（生成文章）需要 human 确认
- 完整推理过程和工具调用都对用户可见
- 历史会话可回看、可续接

### 1.3 范围（In Scope）

- **方向**：自主决策 Agent
- **实现**：原生 LLM Function Calling + 自己写 ReAct 循环
- **生命周期**：短任务（30s-2min，单次响应）
- **交互**：Chat 聊天框
- **工具集**（3 个）：
  - `diagnose_brand`（读，来自 v0.1）
  - `search_knowledge`（读，来自 v0.2）
  - `generate_article`（业务写，仅生成预览，不落库 v0.2，需要 human 确认）
- **知识库角色**：A 模式（agent 只能查，不能改）
- **思考可见**：完整显示 assistant 消息 + 工具调用 + 工具结果
- **历史保存**：所有会话存到数据库
- **多 session**：支持
- **Human-in-the-loop**：写类工具调用前询问

### 1.4 范围外（Out of Scope, v0.4 不做）

- ❌ 多用户系统 / 鉴权 / 团队 / 权限（推到 v1.0）
- ❌ 写类工具的扩展（增删改知识库、上传文档、创建 v0.2 任务、发布、监测）—— agent 只读 + 只预览
- ❌ 工具"增删改查"类元操作（v0.4 工具集内不暴露）
- ❌ agent 直接落库到 v0.1-v0.3 系统（agent 调工具的结果只是"建议"或"预览"，不直接持久化）
- ❌ 多 Agent 协作 / Agent 通信
- ❌ LangGraph / LangChain / Claude SDK 集成（保持 OpenAI SDK）
- ❌ 跨 session 学习 / 用户偏好记忆
- ❌ MCP server 暴露
- ❌ 流式 LLM 输出（v0.4 用 SSE 但 LLM 响应一次性）
- ❌ Voice / 图片 / 文件输入

## 2. 用户与场景

### 2.1 目标用户

**非技术市场人员**（与 v0.1-v0.3 相同）。agent 的目标不是给开发者用的，是给"不懂技术但想用 AI"的品牌运营。

### 2.2 核心场景

**场景 A：完整工作流（"帮我提升小米 GEO 可见度"）**

```
1. 用户在 chat 框输入"帮我提升小米的 GEO 可见度"
2. agent 思考："需要先诊断小米"
   → 调 diagnose_brand 工具（读，直接执行）
3. agent 思考："分数 45，太低。需要查知识库看有什么资料"
   → 调 search_knowledge 工具（读，直接执行）
4. agent 思考："有 3 篇相关资料。我可以基于这些生成优化文章"
   → 调 generate_article 工具（写，需要确认）
5. 前端弹窗："准备生成文章，参数：xxx。是否继续？"
6. 用户点"确认"
7. agent 继续执行 → 生成文章 → 返回结果
8. agent 总结："小米 GEO 分数 45，已基于知识库生成优化文章，请去任务列表审核"
```

**场景 B：单一诊断**

```
1. 用户输入"诊断小米"
2. agent 直接调 diagnose_brand
3. 返回诊断结果 + 简短建议
```

**场景 C：用户取消**

```
1. 用户输入"生成文章"
2. agent 调 generate_article → human confirmation
3. 用户点"取消"
4. agent 收到取消信号 → 回应"已取消"
```

### 2.3 成功标准

- 单轮 agent 响应 < 30s（典型 3 工具调用）
- Human-in-the-loop 弹窗响应 < 100ms
- 历史会话能完整回看
- SSE 流式渲染无明显卡顿

### 3.4 关键设计原则

| 原则 | 实现 |
|---|---|
| **不引入新依赖** | 复用 OpenAI SDK（Function Calling）、FastAPI SSE、SQLite、React |
| **agent 只读 v0.1-v0.3 业务** | 包装调用，不修改 v0.1-v0.3 代码 |
| **写类操作需 human 确认** | 写类工具触发 `pending_confirmation` |
| **完整持久化** | 每条消息（含 tool_calls）都存 DB，可恢复 |
| **可恢复** | 用户刷新 / 离开后回来，能继续 human-in-the-loop |
| **最多 5 轮 ReAct** | 防无限循环 |

### 4.3 工具 3：generate_article

```json
{
  "name": "generate_article",
  "description": "基于指定知识库生成一篇文章草稿。生成前会向用户确认。返回的内容仅供预览，正式发布需要用户去 v0.2 任务列表完成完整任务流程（创建任务 → 生成 → 审核 → 发布）。",
  "parameters": {
    "type": "object",
    "properties": {
      "kb_id": {"type": "string", "description": "知识库 ID"},
      "brand": {"type": "string", "description": "品牌名"},
      "topic": {"type": "string", "description": "文章主题"},
      "keywords": {"type": "array", "items": {"type": "string"}, "description": "关键词"},
      "style": {"type": "string", "enum": ["neutral", "professional", "casual"], "default": "neutral"},
      "target_length": {"type": "integer", "description": "目标字数，默认 1500", "default": 1500}
    },
    "required": ["kb_id", "brand", "topic", "keywords"]
  }
}
```

**类型**：写（业务层面，非工具元操作）| **Human 确认**：✅ 是

**关键澄清**：v0.4 agent 不会**直接修改 v0.2 数据库**（不创建 v0.2 Task / Article）。`generate_article` 工具的"写"是**业务层面**——它会让 LLM 实际调用 v0.2 的 `ContentWriter` 生成内容，但生成结果**只返回给用户预览**，**不直接落库到 v0.2 系统**。如果用户满意预览结果，他需要去 v0.2 任务页**手动触发完整流程**（这与"agent 不写知识库 / 不直接创建任务"的边界一致）。

**执行**（含 human-in-the-loop）：
1. 写"待确认"消息到 `agent_messages` 表（`pending_confirmation=True`）
2. yield SSE 事件 `human_confirmation_required`
3. 暂停，等用户回复
4. 用户确认 → 调 v0.2 `ContentWriter.write_article()` → 返回**预览结果**（不落库到 v0.2）
5. 用户取消 → 返回 cancelled 状态

**返回**：
```python
{
    "status": "generated",
    "title": "...",
    "content_preview": "前 300 字符...",
    "word_count": 1500,
    "next_step": "如满意此预览，请到 /tasks/new 触发完整生成任务",
}
```

## 5. ReAct 循环

### 5.1 循环算法

```python
# app/domain/agent/react_loop.py

MAX_REACT_ITERATIONS = 5  # 防无限循环


async def run_agent_turn(session_id: str, user_message: str) -> AsyncIterator[dict]:
    """执行一轮 agent 推理 + 行动循环。流式 yield SSE 事件。"""
    settings = get_settings()
    llm = LLMClient(settings)
    executor = ToolExecutor(session_id)

    # 1. 加载历史消息
    history = await load_session_messages(session_id)

    # 2. 保存用户消息
    await save_message(session_id, role="user", content=user_message)

    # 3. 构建 messages
    messages = build_messages(history + [{"role": "user", "content": user_message}])

    # 4. ReAct 循环
    for iteration in range(MAX_REACT_ITERATIONS):
        response = await llm.chat_with_tools(messages=messages, tools=TOOLS)

        content = response.get("content", "")
        tool_calls = response.get("tool_calls", [])

        # 保存 assistant 消息
        await save_message(session_id, role="assistant", content=content, tool_calls=...)
        yield {"event": "assistant_message", "content": content}

        if tool_calls:
            for tool_call in tool_calls:
                tool_name = tool_call["function"]["name"]
                tool_args = json.loads(tool_call["function"]["arguments"])
                tool_id = tool_call["id"]

                yield {"event": "tool_call_start", ...}

                try:
                    result = await executor.execute(tool_name, tool_args)
                    await save_message(session_id, role="tool", tool_call_id=tool_id, content=json.dumps(result))
                    yield {"event": "tool_call_result", ...}
                except HumanConfirmationRequired:
                    yield {"event": "human_confirmation_required", ...}
                    await save_message(session_id, role="assistant", content="...", pending_confirmation=True)
                    return  # 退出循环

            messages = build_messages_from_db(session_id)  # 重新加载
        else:
            yield {"event": "turn_complete"}
            return

    yield {"event": "max_iterations_reached", ...}
```

### 5.2 Human-in-the-loop 详细流程

**阶段 A：暂停（写类工具）**

```python
# 在 ToolExecutor.execute_generate_article
async def execute(self, args):
    # 写"待确认"消息
    msg_id = await save_message(
        session_id,
        role="assistant",
        content=f"准备生成文章：\n品牌：{args['brand']}\n主题：{args['topic']}\n...",
        pending_confirmation=True,
    )
    # 抛异常让 ReAct 循环暂停
    raise HumanConfirmationRequired(message_id=msg_id, ...)
```

**阶段 B：用户回复（从断点继续）**

```python
@router.post("/sessions/{session_id}/messages/{message_id}/confirm")
async def confirm_action(session_id, message_id, body: ConfirmActionRequest):
    repo = AgentRepository(session)
    msg = await repo.get_message(message_id)
    if not msg.pending_confirmation:
        raise HTTPException(409)

    await repo.confirm_message(message_id, approved=body.approved)

    if not body.approved:
        await save_message(session_id, role="user", content="取消")
        await save_message(session_id, role="assistant", content="好的，已取消。")
        return {"status": "cancelled"}

    # 重新调用 ReAct 循环（从断点继续）
    return await run_agent_turn_from_checkpoint(session_id, message_id)
```

**关键**：断点续跑**复用已加载的 history**，找到上次的 tool_call，**继续执行**。

## 6. Session 管理

### 6.1 数据模型

```sql
-- Agent 会话
CREATE TABLE agent_sessions (
    id              TEXT PRIMARY KEY,
    title           TEXT NOT NULL,
    created_at      TIMESTAMP NOT NULL,
    updated_at      TIMESTAMP NOT NULL
);

-- Agent 消息
CREATE TABLE agent_messages (
    id              TEXT PRIMARY KEY,
    session_id      TEXT NOT NULL REFERENCES agent_sessions(id) ON DELETE CASCADE,
    role            TEXT NOT NULL,                  -- user / assistant / tool / system
    content         TEXT,
    tool_calls      TEXT,                            -- JSON
    tool_call_id    TEXT,                            -- 关联 assistant 调的工具
    pending_confirmation BOOLEAN DEFAULT 0,
    created_at      TIMESTAMP NOT NULL
);
CREATE INDEX idx_messages_session ON agent_messages(session_id, created_at);
```

### 6.2 Pydantic 模型

# app/models/agent.py

class AgentSession(BaseModel):

class AgentMessage(BaseModel):

    id: str
    session_id: str
    role: AgentMessageRole
    content: str | None
    tool_calls: list[dict] | None
    tool_call_id: str | None

class PendingConfirmation(BaseModel):
    """SSE event payload for human_confirmation_required"""

class SendMessageRequest(BaseModel):

class ConfirmActionRequest(BaseModel):

class CreateSessionRequest(BaseModel):

## 8. SSE 协议

**请求**：
```http
POST /api/agent/sessions/{id}/messages
Content-Type: application/json
{"content": "帮我诊断小米"}
```

**响应**（SSE 流）：
```
event: assistant_message
data: {"content": "好的，让我先诊断小米的 GEO 现状"}

event: tool_call_start
data: {"tool_call_id": "tc_001", "tool_name": "diagnose_brand", "arguments": {...}}

event: tool_call_result
data: {"tool_call_id": "tc_001", "result": {"overall_score": 45, ...}}

event: assistant_message
data: {"content": "分数较低，让我查下知识库..."}

event: human_confirmation_required
data: {"message_id": "msg_xyz", "tool_name": "generate_article", "arguments": {...}}

event: turn_complete
data: {}
```

**前端**（fetch + ReadableStream）：
```typescript
const response = await fetch(`/api/agent/sessions/${id}/messages`, {
  method: 'POST',
  body: JSON.stringify({ content }),
});
const reader = response.body.getReader();
const decoder = new TextDecoder();
let buffer = '';
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  buffer += decoder.decode(value);
  const { events, remainder } = parseSSEEvents(buffer);
  buffer = remainder;
  for (const evt of events) handleAgentEvent(evt);
}
```

## 9. 错误处理

| 错误 | 触发 | 反馈 | 系统行为 |
|---|---|---|---|
| LLM API 失败 | 网络/限额 | 系统消息"AI 服务暂时不可用" | 任务结束 |
| 工具参数错误 | LLM 提供非法参数 | tool result 报错，LLM 重试 | 继续 ReAct |
| 工具业务失败 | v0.1-v0.3 失败 | tool result 报错，LLM 决策 | 继续 ReAct |
| MAX_ITERATIONS | ReAct 5 轮后 | "达到最大推理步数" | 任务结束 |
| session 不存在 | 404 | API 报错 | 前端跳转列表 |
| 消息 ID 错误 | 404 | API 报错 | 重新加载 |
| SSE 断线 | 网络 | "连接断开"提示 | 用户可重试 |
| 工具超时 | 单工具 > 30s | tool result 含错误 | LLM 决策 |
| URL SSRF | diagnose_brand URL 内部 IP | 422 拒绝 | 工具拒绝执行 |

### 9.1 安全

- 工具输入用 Pydantic 验证
- URL 白名单（仅 http/https、非内部 IP）
- 不做 rate limiting（推到 v0.4.x）

## 12. 风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| LLM 工具调用幻觉 | agent 调错工具 | Pydantic 校验 + 严格 schema |
| MAX_ITERATIONS 太小 | 复杂任务提前终止 | 5 轮可调 |
| human-in-the-loop UX 差 | 用户体验割裂 | 清晰的"准备 X，是否继续？" 文案 |
| SSE 断线 | 状态不一致 | 客户端可重连 + 后端续传 |
| URL SSRF | 安全风险 | URL 白名单 + 域名验证 |
| v0.4 工具集太弱 | agent 答非所问 | v0.4.x 加发布/监测工具 |
