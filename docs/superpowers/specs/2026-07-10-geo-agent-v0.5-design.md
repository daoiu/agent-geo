## 1. 背景与目标

### 1.1 背景

v0.2 知识库检索用 jieba 关键词 + SQLite LIKE 检索。对**精确词匹配**有效，但对**语义理解**无能为力：

- 用户搜"产品续航" → 找不到"电池容量大、长续航"段落
- 用户搜"AI 工具评测" → 找不到"大模型应用评估"段落

v0.4 agent 的 `search_knowledge` 工具继承了这个限制。

v0.5 解决：**升级为"关键词 + 向量"混合检索**，让召回率从 ~70% 提升到 ~90%。

### 1.2 目标

v0.5 是个**最小 RAG 骨架**，包含 7 个企业级 RAG 组件中的 3 个最简版本：

| RAG 组件 | v0.5 覆盖 | 状态 |
|---|---|---|
| 1. 数据管道 | ✅ 向量化 | v0.5 做（chunker 沿用 v0.2）|
| 2. 查询理解 | ❌ | 推到 v0.5.x |
| 3. 多路召回 | ✅ 关键词 + 向量 2 路 | v0.5 做 |
| 4. 多层排序 | ✅ RRF（轻量融合）| v0.5 做；cross-encoder rerank 推到 v0.5.x |
| 5. 严格生成 | ✅ v0.4 agent 已做（prompt 约束、引用） | 复用 |
| 6. 持续评估 | ❌ | 推到 v0.5.x / v0.6+ |
| 7. 闭环优化 | ❌ | 推到 v0.6+ |

### 1.3 范围（In Scope）

```python
# app/services/embedding.py
class EmbeddingService:
    """Wraps bge-small-zh-v1.5 via sentence-transformers."""
    
    _model = None  # class-level lazy singleton
    
    @classmethod
    def _get_model(cls):
        if cls._model is None:
            from sentence_transformers import SentenceTransformer
            cls._model = SentenceTransformer(
                "BAAI/bge-small-zh-v1.5",
                cache_folder="./data/models/"
            )
        return cls._model
    
    @classmethod
    def embed(cls, texts: list[str]) -> list[list[float]]:
        model = cls._get_model()
        return model.encode(texts, normalize_embeddings=True).tolist()


# app/domain/knowledge/vector_index.py
class VectorIndex:
    """ChromaDB wrapper for a knowledge base's chunk vectors."""
    
    _client = None  # class-level singleton (ChromaDB client is thread-safe)
    
    @classmethod
    def _get_client(cls):
        if cls._client is None:
            import chromadb
            cls._client = chromadb.PersistentClient(path="./data/chroma/")
        return cls._client
    
    def __init__(self, kb_id: str):
        self._client = self._get_client()
        self._collection_name = f"kb_{kb_id}"
        self._collection = self._get_or_create_collection()
    
    def add_chunks(self, chunks: list[dict]) -> None:
        """chunks: [{'id', 'content', 'doc_id', 'chunk_index'}, ...]"""
        if not chunks:
            return
        ids = [c["id"] for c in chunks]
        texts = [c["content"] for c in chunks]
        metadatas = [
            {"doc_id": c["doc_id"], "chunk_index": c["chunk_index"], "kb_id": self._collection_name}
            for c in chunks
        ]
        self._collection.add(ids=ids, documents=texts, metadatas=metadatas)
    
    def query(self, query_text: str, top_k: int = 10) -> list[dict]:
        """Returns [{'id', 'content', 'metadata', 'distance'}, ...]"""
        results = self._collection.query(
            query_texts=[query_text],
            n_results=top_k,
        )
        # ChromaDB returns nested lists; flatten
        ids = results["ids"][0] if results["ids"] else []
        docs = results["documents"][0] if results["documents"] else []
        metas = results["metadatas"][0] if results["metadatas"] else []
        dists = results["distances"][0] if results["distances"] else []
        return [
            {
                "id": ids[i],
                "content": docs[i],
                "metadata": metas[i],
                "distance": dists[i] if i < len(dists) else None,
            }
            for i in range(len(ids))
        ]
    
    def delete_chunks(self, chunk_ids: list[str]) -> None:
        if chunk_ids:
            self._collection.delete(ids=chunk_ids)
    
    def get_all_ids(self) -> set[str]:
        """Get all indexed chunk IDs (for reindex diff)."""
        result = self._collection.get()
        return set(result["ids"])
```

## 5. 混合检索（RRF）

### 5.1 RRF 算法

**Reciprocal Rank Fusion** 是学术界标准的轻量级多路融合算法（Cormack et al. 2009）。

**核心思想**：每个检索器给每个 chunk 打 rank，按 `1 / (k + rank)` 加权融合，避免不同检索器的分数 scale 不可比问题。

```python
def rrf_fusion(
    vector_results: list[dict],
    keyword_results: list[dict],
    top_k: int = 5,
    k: int = 60,  # RRF constant, typical value 50-60
) -> list[dict]:
    """
    Merge two ranked lists via RRF.

    Final score = sum(1 / (k + rank)) for each list the chunk appears in.
    """
    scores: dict[str, float] = {}
    chunk_data: dict[str, dict] = {}

    # Process vector results
    for rank, chunk in enumerate(vector_results, start=1):
        cid = chunk["id"]
        scores[cid] = scores.get(cid, 0.0) + 1.0 / (k + rank)
        chunk_data[cid] = {**chunk, "_sources": ["vector"]}

    # Process keyword results
    for rank, chunk in enumerate(keyword_results, start=1):
        cid = chunk["id"]
        scores[cid] = scores.get(cid, 0.0) + 1.0 / (k + rank)
        if cid in chunk_data:
            chunk_data[cid]["_sources"] = chunk_data[cid].get("_sources", []) + ["keyword"]
        else:
            chunk_data[cid] = {**chunk, "_sources": ["keyword"]}

    # Sort by RRF score
    sorted_ids = sorted(scores.keys(), key=lambda x: -scores[x])
    return [{**chunk_data[cid], "_rrf_score": scores[cid]} for cid in sorted_ids[:top_k]]
```

```python
# app/services/hybrid_search.py
class HybridSearch:
    """Combines vector search (ChromaDB) + keyword search (SQLite LIKE) via RRF."""

    def __init__(self):
        self._embedding = EmbeddingService
    
    async def search(
        self,
        kb_id: str,
        query: str,
        top_k: int = 5,
    ) -> list[dict]:
        try:
            return await self._hybrid_search(kb_id, query, top_k)
        except Exception as e:
            logger.warning("hybrid_search_failed, falling back to keyword", error=str(e))
            return await self._keyword_search(kb_id, query, top_k)
    
    async def _hybrid_search(self, kb_id, query, top_k):
        # 1. Vector search
        vector_results = self._vector_search(kb_id, query, top_k=20)
        # 2. Keyword search
        keyword_results = await self._keyword_search(kb_id, query, top_k=20)
        # 3. RRF fusion
        return rrf_fusion(vector_results, keyword_results, top_k=top_k)
    
    def _vector_search(self, kb_id, query, top_k):
        index = VectorIndex(kb_id)
        return index.query(query_text=query, top_k=top_k)
    
    async def _keyword_search(self, kb_id, query, top_k):
        """Use existing v0.2 jieba-based keyword search."""
        import jieba
        from app.repositories.knowledge_repo import KnowledgeRepository
        from app.core.db import get_session_factory
        
        keywords = [w for w in jieba.cut(query) if len(w.strip()) > 1]
        if not keywords:
            return []
        async with get_session_factory()() as session:
            repo = KnowledgeRepository(session)
            chunks = await repo.search_chunks_by_keyword(
                kb_id=kb_id, keywords=keywords, top_k=top_k
            )
        return [
            {
                "id": c.id,
                "content": c.content,
                "metadata": {"doc_id": c.doc_id, "chunk_index": c.chunk_index, "kb_id": c.kb_id},
            }
            for c in chunks
        ]
```

## 6. 启动 Lazy 向量化

### 6.1 目标

v0.5 第一次启动时，自动把 v0.2 已有的 chunks 全部向量化。增量运行：每次启动只处理新增的 chunks。

### 6.2 ReindexService

```python
# app/services/reindex.py
class ReindexService:
    """Vectorize chunks that don't yet have a vector in ChromaDB."""

    async def reindex_all(self) -> dict:
        """Find and index all chunks missing from ChromaDB.
        
        Returns stats: {kb_id: {total, indexed, skipped}}
        """
        from app.core.db import get_session_factory
        from app.repositories.knowledge_repo import KnowledgeRepository
        from app.domain.knowledge.vector_index import VectorIndex

        stats = {}
        async with get_session_factory()() as session:
            repo = KnowledgeRepository(session)
            kbs = await repo.list_knowledge_bases()

            for kb in kbs:
                kb_stats = await self._reindex_one_kb(repo, kb.id)
                stats[kb.id] = kb_stats

        return stats

    async def _reindex_one_kb(self, repo, kb_id: str) -> dict:
        # 1. Get all chunks from SQLite
        all_chunks = await repo.list_chunks(kb_id)
        if not all_chunks:
            return {"total": 0, "indexed": 0, "skipped": 0}

        # 2. Get already-indexed IDs from ChromaDB
        index = VectorIndex(kb_id)
        indexed_ids = index.get_all_ids()

        # 3. Find chunks to index
        to_index = [c for c in all_chunks if c.id not in indexed_ids]
        if not to_index:
            return {"total": len(all_chunks), "indexed": 0, "skipped": len(all_chunks)}

        # 4. Embed + index in batches
        BATCH_SIZE = 50
        for i in range(0, len(to_index), BATCH_SIZE):
            batch = to_index[i:i + BATCH_SIZE]
            texts = [c.content for c in batch]
            embeddings = EmbeddingService.embed(texts)
            # ChromaDB supports passing pre-computed embeddings
            index._collection.add(
                ids=[c.id for c in batch],
                documents=texts,
                embeddings=embeddings,
                metadatas=[
                    {"doc_id": c.doc_id, "chunk_index": c.chunk_index, "kb_id": kb_id}
                    for c in batch
                ],
            )

        return {
            "total": len(all_chunks),
            "indexed": len(to_index),
            "skipped": len(all_chunks) - len(to_index),
        }
```

## 8. 降级策略

### 8.1 优先级

```
hybrid_search 优先级：
1. 尝试：vector + keyword → RRF 融合
   - 如果 vector 失败 → 降级到 keyword
   - 如果 RRF 融合失败 → 降级到 keyword
2. 尝试：纯 keyword
   - 如果 keyword 失败 → 返回空 + 错误
3. 永远不报错给用户：降级而非崩溃
```

## 9. 错误处理

| 错误 | 触发 | 反馈 | 系统行为 |
|---|---|---|---|
| ChromaDB 启动失败 | 文件路径权限、磁盘满 | 启动失败 | 阻塞启动 |
| bge 模型下载失败 | 无网络/磁盘满 | 启动失败 | 阻塞启动 |
| bge 模型加载失败 | 模型文件损坏 | 启动失败 | 阻塞启动 |
| embed 失败 | 单 chunk 内容异常 | 跳过该 chunk | 记录日志，不影响整体 |
| ChromaDB query 失败 | collection 不存在 | 降级到纯关键词 | 记录 warning |
| RRF 融合空结果 | 两检索器都返回空 | 返回空列表 | 正常 |
| v0.2 上传但 ChromaDB 添加失败 | 写入不一致 | 标记 `pending_index=1` | 下次 lazy reindex 补 |
| 删除文档但 ChromaDB 删除失败 | 同上 | 标记"待清理" | 下次启动 lazy reindex 处理 |

## 13. 未来 v0.5.x 升级路径

> **v0.5 是"最小 RAG 骨架"**——只覆盖企业级 RAG 7 个组件中的 3 个最简版本。
> 以下升级路径**不在 v0.5 范围**，但 v0.5 spec 留好升级接口。

### 13.1 v0.5.1 — Cross-encoder Rerank（**最优先**）

**目标**：在 RRF 之后加一层 cross-encoder rerank，检索准确率 +10-15%

**模型**：`BAAI/bge-reranker-large`（~2GB，CPU/GPU 都行）

**架构变化**：
```
向量检索 top-20 → RRF 融合 → cross-encoder rerank top-5
```

**实施成本**：中（加模型 + 推理）

**收益**：
- 检索准确率从 ~85% → ~95%
- 解决 RRF 不能"重排"的局限（RRF 只融合不重排）

### 13.2 v0.5.2 — HyDE（Hypothetical Document Embedding）

**目标**：用 LLM 生成"假设文档"再 embedding，提升召回率

**原理**：用户问"产品续航" → LLM 想象一篇关于产品续航的文章 → 嵌入文章 → 检索

**架构变化**：
```
query → LLM 生成假设文档 → embed 假设文档 → 向量检索
```

**实施成本**：低（v0.4 agent 已能调 LLM，免费复用）

**收益**：召回率 +5-10%（尤其短查询）

### 13.3 v0.5.3 — Query Rewriting

**目标**：让 LLM 改写 query 再检索（处理模糊/口语化 query）

**原理**：用户问"小米那手机咋样" → LLM 改写为"小米手机的优缺点" → 检索

**架构变化**：
```
query → LLM 改写 → 多个改写版本 → 各自检索 → 融合
```

**实施成本**：低（v0.4 agent 已有此能力）

**收益**：召回率 +5%（尤其口语化查询）

### 13.4 v0.6+ — 持续评估 + 闭环优化

**目标**：建立评估体系，实现"系统自己变好"

**评估**：
- **离线评估**：用 100 个测试 query 对比纯向量 vs 混合 vs hybrid+rerank 的 NDCG@5
- **在线评估**：v0.4 agent human-in-the-loop 的"批准/拒绝"作为隐式反馈

**闭环**：
- 用户拒绝某次生成 → 触发"重新检索"
- 检索失败率高 → 自动调优 prompt 或重新向量化

**实施成本**：高（需要评估数据 + 评估流水线 + 自动 retrain）
