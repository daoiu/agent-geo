## 1. 背景与目标

### 1.1 背景

v0.1 实现了 GEO 诊断，v0.2 实现了基于知识库的内容生成。v0.2 流程终止于"人工批准 Article"，但已批准的文章还在本地数据库中，没法真正发布到客户能看到的渠道。

v0.3 解决"从审核通过到外网可见"的最后一公里，并提供持续监测能力，让品牌方能看到发布后的真实效果。

### 1.2 目标

为 v0.2 的"已批准 Article"提供：
1. **WordPress 自动发布**：通过 WordPress REST API 一键发布
2. **AI 答案持续监测**：周期性检测品牌在 AI 答案中的提及率
3. **变化趋势可视化**：折线图显示历史监测数据
4. **邮件通知**：发布完成、监测到显著变化时主动通知

### 1.3 范围（In Scope）

- 4 个能力：**WordPress 发布 / AI 答案监测 / 趋势图 / 邮件通知**
- 单发布平台：WordPress（Application Password 认证）
- 调度方案：APScheduler（单进程内）
- 监测触发：用户独立创建监测任务
- 通知渠道：邮件（SMTP）
- 中文字体支持

### 1.4 范围外（Out of Scope, v0.3 不做）

- ❌ 公众号发布（v0.4+）
- ❌ Slack / 企业微信 / 钉钉通知
- ❌ Playwright 渲染 SPA（v0.6）
- ❌ 多用户系统（v0.4）
- ❌ Celery + Redis 分布式调度
- ❌ 跨监测任务的对比分析
- ❌ 监测模板（用户每次手填）
- ❌ 自动重试失败发布（v0.3 用户手动重试）

## 2. 用户与场景

### 2.1 目标用户

**品牌方市场人员 / GEO 代运营**（与 v0.1/v0.2 相同用户群）

### 2.2 核心使用场景

**场景 A：发布审核通过的文章**
```
1. v0.2 审核通过 Article A
2. 用户进 /publishes，点"创建发布"
3. 选 Article A + 选 WordPress 凭证
4. 创建 publish_job
5. Worker 调 WordPress REST API
6. 成功 → 邮件通知 + 页面显示 remote_url
```

**场景 B：建立长期监测**
```
1. 用户进 /monitors/new
2. 填：品牌、行业、3-5 个问题、频率 daily、通知邮箱
3. 创建 monitor_task
4. APScheduler 加入调度
5. 每天自动跑一次 → 创建 snapshot
6. 变化超过 15% → 发邮件
7. 用户在 /monitors/{id} 看趋势图
```

**场景 C：诊断 + 生成 + 发布 + 监测 完整链路**
```
1. v0.1 诊断（小米品牌）
2. 基于诊断创建 v0.2 任务
3. AI 生成 + 审核通过
4. v0.3 发布到 WordPress
5. v0.3 建立监测任务，持续追踪
6. 一个月后看趋势图，评估发布效果
```

### 2.3 成功标准

- 发布审核通过的 Article：90s 内完成 WordPress 发布
- 监测任务创建后：24 小时内首次执行
- 进程重启后：监测调度自动恢复
- 监测变化超阈值：5 分钟内发邮件

### 5.1 WordPress 发布子系统

**REST API**：

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/publishers` | 列出所有 WordPress 凭证 |
| POST | `/api/publishers` | 添加凭证（test connection 验证）|
| GET | `/api/publishers/{id}` | 凭证详情（app_password 隐藏）|
| PUT | `/api/publishers/{id}` | 更新凭证 |
| DELETE | `/api/publishers/{id}` | 删除（有关联 publish_job 时 409）|
| POST | `/api/publishers/{id}/test` | 测试连通性（调 `/wp/v2/users/me`）|
| GET | `/api/publishes` | 发布任务列表（可按 status 过滤）|
| POST | `/api/publishes` | 创建发布任务（article_id + config_id）|
| GET | `/api/publishes/{id}` | 发布任务详情 |
| POST | `/api/publishes/{id}/retry` | 重试 failed 任务 |
| POST | `/api/publishes/{id}/cancel` | 取消 pending/running 任务 |

**WordPress REST 集成**：
- 认证：Basic Auth with Application Password
- 端点：`POST {site_url}/wp-json/wp/v2/posts`
- 请求体：`{ "title": "...", "content": "...", "status": "publish" }`
- 成功响应（201）：`{ "id": 123, "link": "https://..." }`

**文章格式转换**：Markdown → HTML（用 `markdown` Python 库）

**凭证加密存储**：
- 用 `cryptography.Fernet` 对称加密
- 密钥从 `.env` 的 `ENCRYPTION_KEY`（32 字节 base64）读取
- 写入 DB 前 `encrypt()`，读出后 `decrypt()`
- 启动时若 `.env` 没设 `ENCRYPTION_KEY` → 服务启动失败

**发布状态机**：

```
pending ──> running ──> success
              │
              ├──> failed（可重试）
              └──> cancelled（用户取消）
```

**关键算法**：

```python
async def execute_publish(publish_job_id: str) -> None:
    factory = get_session_factory()
    cipher = get_cipher()

    async with factory() as session:
        repo = PublishRepository(session)
        job = await repo.get_publish_job(publish_job_id)
        if job is None or job.status != "pending":
            return

        await repo.update_publish_job_status(publish_job_id, status="running")

        try:
            article = await repo.get_article(job.article_id)
            if article is None:
                raise PublishError("article not found")
            if article.review_status != "approved":
                raise PublishError(f"article not approved (status: {article.review_status})")

            config = await repo.get_publisher_config(job.config_id)
            app_password = cipher.decrypt(config.app_password_encrypted).decode()

            html = markdown.markdown(
                article.content or "",
                extensions=["extra", "sane_lists", "toc"],
            )

            async with httpx.AsyncClient(timeout=30.0) as client:
                response = await client.post(
                    f"{config.site_url}/wp-json/wp/v2/posts",
                    auth=(config.username, app_password),
                    json={
                        "title": job.title_override or article.title or "Untitled",
                        "content": html,
                        "status": "publish",
                    },
                )

            if response.status_code == 201:
                data = response.json()
                await repo.update_publish_job_success(
                    publish_job_id,
                    remote_post_id=data["id"],
                    remote_url=data["link"],
                )
                await notification_service.notify_publish_success(job, data["link"])
            elif response.status_code == 401:
                raise PublishError("认证失败：用户名或 Application Password 错误")
            elif response.status_code == 403:
                raise PublishError("权限不足：用户没有发布权限")
            elif response.status_code == 404:
                raise PublishError("WordPress 站点 URL 错误或 REST API 未启用")
            else:
                raise PublishError(
                    f"WordPress API 错误 {response.status_code}: {response.text[:200]}"
                )
        except Exception as e:
            await repo.update_publish_job_status(
                publish_job_id, status="failed", error=str(e)
            )
            await notification_service.notify_publish_failure(job, str(e))
```

```python
# app/domain/monitor/scheduler.py

_scheduler: AsyncIOScheduler | None = None


def get_scheduler() -> AsyncIOScheduler:
    global _scheduler
    if _scheduler is None:
        _scheduler = AsyncIOScheduler()
    return _scheduler


def frequency_to_interval(freq: MonitorFrequency) -> timedelta:
    return {
        MonitorFrequency.HOURLY: timedelta(hours=1),
        MonitorFrequency.DAILY: timedelta(days=1),
        MonitorFrequency.WEEKLY: timedelta(weeks=1),
    }[freq]


def schedule_monitor_task(task) -> None:
    scheduler = get_scheduler()
    job_id = f"monitor_{task.id}"
    if scheduler.get_job(job_id):
        scheduler.remove_job(job_id)
    if not task.is_active:
        return
    interval = frequency_to_interval(MonitorFrequency(task.frequency))
    scheduler.add_job(
        execute_monitor_run,
        trigger=IntervalTrigger(seconds=interval.total_seconds()),
        args=[task.id],
        id=job_id,
        replace_existing=True,
        next_run_time=task.next_run_at,
    )


def unschedule_monitor_task(task_id: str) -> None:
    scheduler = get_scheduler()
    job_id = f"monitor_{task_id}"
    if scheduler.get_job(job_id):
        scheduler.remove_job(job_id)


async def load_all_monitor_tasks() -> None:
    """On startup, reload all active monitor tasks from DB."""
    factory = get_session_factory()
    async with factory() as session:
        repo = MonitorRepository(session)
        tasks = await repo.list_active_monitor_tasks()
        for task in tasks:
            schedule_monitor_task(task)
```

**单次监测执行**：

```python
async def execute_monitor_run(monitor_task_id: str) -> None:
    factory = get_session_factory()
    async with factory() as session:
        repo = MonitorRepository(session)
        task = await repo.get_monitor_task(monitor_task_id)
        if task is None or not task.is_active:
            return

        await repo.update_monitor_last_run(monitor_task_id, datetime.utcnow())

        try:
            settings = get_settings()
            llm = LLMClient(settings)
            mentions = await llm.query_mentions(
                brand=task.brand,
                industry=task.industry,
                questions=task.target_questions,
                providers=task.providers,
            )

            valid = [m for m in mentions if m.error is None]
            mentioned = [m for m in valid if m.brand_mentioned]
            rate = len(mentioned) / len(valid) if valid else 0.0
            avg_pos = (
                sum(m.mention_position for m in mentioned if m.mention_position) / len(mentioned)
                if mentioned else None
            )

            snapshot_id = await repo.create_snapshot(
                monitor_task_id=monitor_task_id,
                mention_rate=rate,
                mention_count=len(mentioned),
                total_samples=len(valid),
                avg_position=avg_pos,
                details=[m.model_dump() for m in mentions],
            )

            if task.notify_email:
                await check_and_notify_change(task, rate, snapshot_id)
        except Exception as e:
            logger.exception("monitor_run_failed", task_id=monitor_task_id)
            await repo.create_snapshot(
                monitor_task_id=monitor_task_id,
                mention_rate=0.0,
                mention_count=0,
                total_samples=0,
                avg_position=None,
                details=[],
                error_message=str(e),
            )
```

**通知触发**：

```python
async def check_and_notify_change(task, current_rate, snapshot_id) -> None:
    if not task.notify_email:
        return

    repo = MonitorRepository(session)
    previous = await repo.get_previous_snapshot(task.id, before=snapshot_id)
    if previous is None:
        return

    delta = abs(current_rate - previous.mention_rate)
    if delta < task.change_threshold:
        return

    direction = "上升" if current_rate > previous.mention_rate else "下降"
    subject = f"[GEO 监测] {task.name} - 提及率{direction} {delta*100:.1f}%"
    body = f"""品牌：{task.brand}
当前提及率：{current_rate * 100:.1f}%
上次提及率：{previous.mention_rate * 100:.1f}%
变化：{direction} {delta * 100:.1f}%（阈值 {task.change_threshold * 100:.0f}%）
执行时间：{datetime.utcnow().isoformat()}

查看详情：http://localhost:5173/monitors/{task.id}
"""
    await notification_service.send_email(
        to=task.notify_email,
        subject=subject,
        body=body,
    )
```

## 6. 错误处理

| 错误 | 触发 | 反馈 | 系统行为 |
|---|---|---|---|
| WordPress 401 | 凭证错 | "用户名或 Application Password 错误" | publish_job failed |
| WordPress 403 | 无权限 | "用户没有发布权限" | publish_job failed |
| WordPress 404 | 站点错 | "WordPress 站点 URL 错误" | publish_job failed |
| WordPress 5xx | 服务端错 | "WordPress 服务端错误" | publish_job failed |
| 网络超时 | 30s | "请求超时" | publish_job failed |
| LLM 调用失败（监测） | API 错 | snapshot.error_message | 任务继续 |
| LLM 部分失败 | 部分 question 错 | mention_rate 基于成功样本 | 任务继续 |
| SMTP 配置缺失 | .env 没配 | 通知静默跳过 | 任务继续 |
| SMTP 发送失败 | 网络/认证错 | 日志记录 | 任务继续 |
| 调度器重启 | 进程重启 | 启动时从 DB 恢复 | 透明 |
| 删凭证有 publish_job | 有依赖 | 409 拒绝 | 拒绝 |
| 发未审核文章 | review_status != approved | 422 拒绝 | 拒绝 |
| 监测 brand 空 | 422 校验 | 拒绝 | 拒绝 |
| APScheduler 启动失败 | 配置错 | 启动失败 | 服务无法启动 |
| 加密密钥缺失 | .env 没 ENCRYPTION_KEY | 启动失败 | 服务无法启动 |

## 9. 风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| WordPress 站点版本差异 | REST API 行为不同 | 测试目标 WP 5.6+ 文档接口 |
| 公众号 API 不在 v0.3 范围 | 用户期望缺失 | 在 UI 明确标注"v0.4 推出" |
| LLM API 配额耗尽 | 监测全失败 | 用户责任，配置 .env 时提示 |
| 邮件进入垃圾箱 | 通知失效 | 用企业邮箱 + SPF/DKIM |
| APScheduler 进程内调度 | 重启延迟 | 启动时从 DB 加载 |
| WordPress 站被墙 | 国内用户 | 提示用户站点需要公网访问 |
| TLS 证书过期 | 发布失败 | 错误信息明确指出 TLS |
