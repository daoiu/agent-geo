## 1. 背景与目标

### 1.1 背景

v0.1 实现了**GEO 诊断**——告诉品牌"你的 GEO 健康度如何，缺什么"。

v0.2 在此基础上实现**"基于知识库的内容生成"**——告诉品牌"基于你提供的资料，AI 能生成什么样的内容供你审核使用"。

参考了开源项目 [GEOFlow](D:\GEO\GEOFlow) 后明确了主流 GEO 工具的形态：**知识库底座 + RAG 检索 + AI 生成 + 人工审核** 是行业标准工作流。v0.2 用精简版实现这个闭环。

### 1.2 目标

为同一批目标用户（非技术市场人员）提供：
- 知识库管理：上传 PDF / Word / Markdown / TXT 文件
- 任务调度：创建内容生成任务（基于知识库 + 主题 + 关键词）
- AI 生成：基于知识库真实信息生成文章（**不得编造参考资料**）
- 人工审核：审核队列，批准 / 拒绝生成的文章

### 1.3 范围（In Scope）

- 4 个子模块：**知识库 / 任务 / 生成 / 审核**
- 支持 4 种文件类型：PDF / Word / Markdown / TXT
- 关键词检索（不做向量检索，v0.5 升级）
- 中文生成（v0.2 暂不做多语言）
- 单人使用（无角色权限）

### 1.4 范围外（Out of Scope, v0.2 不做）

- ❌ 用户登录鉴权（推到 v0.4）
- ❌ 多站点分发（v0.3）
- ❌ LLM 友好站点包 llms.txt / Schema / 静态页（v0.3+）
- ❌ 向量检索（v0.5 升级）
- ❌ 多角色权限（v0.4）
- ❌ 爬虫识别 / 数据分析（v0.3+）
- ❌ 智能推荐主题（v0.3+）
- ❌ 多语言内容（v0.3+）

## 2. 用户与场景

### 2.1 目标用户

**非技术市场人员**（与 v0.1 相同用户群）

特征：
- 懂业务不懂技术
- 拥有公司内部资料（白皮书、产品手册、FAQ 文档等）
- 不想从零写文章，但能从 AI 生成的内容基础上审核修改

### 2.2 核心使用场景

**场景 A：从 v0.1 诊断进入生成**

```
1. 用户在 v0.1 报告页看到诊断结果
2. 点"基于此诊断创建生成任务"
3. 跳转到 v0.2 任务创建页（预填诊断里的目标问题作为主题）
4. 用户选知识库（或上传新文件）
5. 创建任务
6. 进入审核队列审核 AI 生成的文章
```

**场景 B：直接使用 v0.2**

```
1. 用户进入"知识库"页面
2. 创建新知识库 + 上传 PDF / Word 文件
3. 等待解析完成
4. 创建任务（指定主题 + 文章数量）
5. Worker 异步生成
6. 进入审核队列逐篇审核
```

### 2.3 成功标准

- 上传 4 种文件 → 全部解析成功
- 创建任务 → 60 秒内启动 Worker
- 5 篇文章生成 → 5 分钟内完成（取决于 LLM 响应）
- 审核操作响应 < 500ms
- 端到端流程无需重启服务

### 3.4 v0.2 端到端流程

```
1. 用户上传文件（PDF/Word/MD/TXT）到知识库
   ↓
2. Worker 解析文件 → chunker 切片 → 入库
   ↓
3. 用户创建任务：选知识库 + 主题 + 关键词 + 文章数量
   ↓
4. 任务进入 pending → Worker 异步启动
   ↓
5. Worker 为每篇文章：
   - 关键词检索召回 top 5 片段
   - 拼装 prompt（主题 + 召回片段 + 风格 + 长度）
   - 调用 LLM 生成
   - 创建 Article（status=draft, review_status=pending）
   ↓
6. 用户进入审核队列
   ↓
7. 逐篇审核：批准 / 拒绝（带理由）
   ↓
8. 任务完成（所有文章审核完毕）
```

**切片算法**：

```python
def chunk_text(text: str) -> list[str]:
    """规则：
    1. 优先按段落（\\n\\n）切
    2. 单段落 > 500 字 → 切到 500 字（按句子边界）
    3. 单段落 < 50 字 → 与下一段落合并
    4. 最终每片 50-500 字
    """
    paragraphs = text.split("\n\n")
    chunks = []
    buffer = ""
    for p in paragraphs:
        p = p.strip()
        if not p:
            continue
        if len(p) > 500:
            if buffer:
                chunks.append(buffer)
                buffer = ""
            # 长段落按句子切
            chunks.extend(_split_long(p, 500))
        elif len(buffer) + len(p) > 500:
            chunks.append(buffer)
            buffer = p
        else:
            buffer = buffer + "\n\n" + p if buffer else p
    if buffer:
        chunks.append(buffer)
    return [c for c in chunks if len(c) >= 50]
```

**关键词检索**（v0.2 简化版）：

```python
def search_chunks(kb_id: str, query: str, top_k: int = 5) -> list[KnowledgeChunk]:
    """SQL LIKE 匹配 + 简单词频排序。
    v0.5 升级为 pgvector + embedding。
    """
    # 使用 jieba 做中文分词（轻量、纯 Python）
    import jieba
    keywords = [w for w in jieba.cut(query) if len(w.strip()) > 1]
    # 过滤停用词（简化版：直接长度 > 1）
    rows = await db.execute(
        select(KnowledgeChunk)
        .where(KnowledgeChunk.kb_id == kb_id)
    )
    scored = []
    for chunk in rows:
        score = sum(1 for kw in keywords if kw in chunk.content)
        if score > 0:
            scored.append((score, chunk))
    scored.sort(key=lambda x: -x[0])
    return [c for _, c in scored[:top_k]]
```

**任务执行流程**：

```python
async def run_task(task_id: str):
    task = await repo.get_task(task_id)
    try:
        task.status = TaskStatus.RUNNING
        await repo.save(task)

        # 创建 N 个占位文章
        for i in range(task.article_count):
            article = ArticleORM(
                id=str(uuid.uuid4()),
                task_id=task_id,
                title=f"待生成 #{i+1}",
                review_status=ReviewStatus.PENDING,
            )
            await repo.save(article)

        # 顺序生成（不并行避免 LLM 配额超限）
        articles = await repo.list_articles(task_id)
        for i, article in enumerate(articles):
            if task.status == TaskStatus.CANCELLED:
                break
            try:
                await generate_one_article(task, article)
            except LlmError as e:
                article.error_message = str(e)
                article.title = f"生成失败 #{i+1}"
                logger.warning("llm_error", task_id=task_id, error=str(e))
            except Exception as e:
                article.error_message = f"unexpected: {e}"
                article.title = f"生成失败 #{i+1}"
                logger.exception("unexpected_error", task_id=task_id)
            await repo.save(article)

            task.progress = int((i + 1) / task.article_count * 100)
            await repo.save(task)

        task.status = TaskStatus.COMPLETED
    except Exception as e:
        task.status = TaskStatus.FAILED
        task.error_message = str(e)
        logger.exception("task_failed", task_id=task_id)
    finally:
        await repo.save(task)
```

### 5.3 生成子系统

**单篇生成流程**：

```python
async def generate_one_article(task: Task, article: ArticleORM) -> None:
    # 1. 检索：关键词召回
    chunks = await retriever.search(
        kb_id=task.kb_id,
        query=task.topic + " " + " ".join(task.keywords),
        top_k=5,
    )

    # 2. 拼装 prompt
    prompt = prompt_builder.build(
        topic=task.topic,
        keywords=task.keywords,
        style=task.style,
        target_length=task.target_length,
        chunks=chunks,
    )

    # 3. 调用 LLM（直接用 v0.1 的 llm_client）
    response = await llm_client.generate(prompt)

    # 4. 抽取标题
    title = extract_title(response) or f"未命名文章 #{article.title}"

    # 5. 更新文章
    article.title = title
    article.content = response
    article.content_length = len(response)
    article.cited_chunks = json.dumps([c.id for c in chunks])
    article.llm_provider = settings.enabled_providers[0]
```

**Prompt 模板**：

```
你是 {brand} 的内容编辑。基于以下"参考资料"撰写一篇文章。

【主题】{topic}
【关键词】{keywords}
【风格】{style}
【目标字数】约 {target_length} 字

【参考资料】（请基于这些真实信息撰写，不得编造参考资料中没有的事实）
---
{chunk_1_content}

{chunk_2_content}

...

{chunk_5_content}
---

要求：
1. 文章结构：标题（H1）、引言、3-5 个 H2 章节、结论
2. 每段开头直接给出核心主张（BLUF 原则）
3. 引用参考资料时用 [1] [2] 等标注
4. 不得编造参考资料中没有的数据、价格、案例
5. 不得使用"作为 AI 模型"等元话语

输出 Markdown 格式。
```

**关键设计点**：
- ✅ "不得编造参考资料" = 白帽 GEO 的核心约束
- ✅ 引用标注 = 审核者知道哪些是引用、哪些是 AI 加的
- ✅ 拒绝元话语 = 避免 AI 痕迹过重

## 6. 错误处理

### 6.1 错误分类

| 错误类型 | 触发场景 | 用户反馈 | 系统行为 |
|---|---|---|---|
| 文件解析失败 | PDF 损坏、Word 加密 | 文档列表显示"解析失败" + 原因 | 其他文档继续 |
| 切片后空文档 | 解析成功但内容 < 50 字 | 文档显示"内容过短" | 保留但 chunk_count=0 |
| 任务无知识库 | 创建时 kb_id 不存在 | 422 校验 | 拒绝创建 |
| LLM 生成失败 | API key 错、超时、配额耗尽 | 文章 draft + error_message | 任务继续下一篇 |
| 任务中途取消 | 用户取消 running 任务 | 任务 cancelled | 已生成保留为 draft |
| 删除知识库有任务依赖 | 任务还在用 | 409 Conflict | 提示先删任务 |
| 文件过大 | > 50MB | 422 | 拒绝 |
| 文件类型不支持 | .exe / .zip | 415 | 拒绝 |
| 关键词检索无结果 | 知识库没有相关内容 | 提示"知识库可能不够丰富" | 文章仍生成，prompt 标注"无参考资料" |

### 6.2 异常类（继承 v0.1 的 DomainError）

```python
class KnowledgeError(DomainError): pass
class DocumentParseError(KnowledgeError): ...
class ChunkingError(KnowledgeError): pass

class TaskError(DomainError): pass
class TaskNotFoundError(TaskError): pass
class TaskStateError(TaskError): pass

class GenerationError(DomainError): pass

class ReviewError(DomainError): pass
```

### 6.3 错误处理关键设计

**单篇生成失败不让整个任务失败**。失败文章进入审核队列，让用户决定重试或丢弃。

**任务取消的优雅退出**：Worker 在每篇生成前检查 `task.status == CANCELLED`，已生成的文章保留为 draft。

## 10. 风险与已知短板

| 风险 | 影响 | 缓解 |
|---|---|---|
| LLM 幻觉（生成参考资料外内容）| 文章不真实 | Prompt 强约束 + 审核环节兜底 |
| 关键词检索召回不准 | 文章可能跑题 | v0.5 升级向量检索 |
| 50MB 文件解析慢 | 用户等待 | 异步处理 + 状态展示 |
| Worker 单飞导致任务串行 | 长任务耗时 | MVP 接受，v0.3 改 Celery |
| 中文 OCR PDF | 文本提取失败 | 文档标记"无法解析"，由用户决定 |
| 任务删除时 Worker 在跑 | 数据不一致 | Worker 检查 cancelled 标志 |
