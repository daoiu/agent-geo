## 1. 背景与动机

### 1.1 当前差距

后端在 7/14 之后改了一大圈(25+ commits),前端从 v0.6 P0 之后基本停止:

**后端已新增但前端未接入:**
- LangGraph 替换 react_loop 主循环(SSE 事件 schema 调整)
- Multi-Agent 拆分(ContentWriter / Monitor Specialist + handoff 协议 + HandoffLogORM)
- Replay API `POST /sessions/{sid}/replay/{msg_id}`
- 月度成本 dashboard(P2#49)
- 故障注入工具 FaultInjector(P2#31)
- 自适应压缩 + 截断决策可解释(P2#36/37)
- HITL reject 理由进入 LLM 上下文(P1#26)
- device_id + L2 memory injection
- cross-KB global hybrid recall(v0.6 P1.3)
- 文章详情 .md 下载(v0.6 P1.5)

**前端状态:** 122 个 tsx/ts 文件,24 个页面;App.tsx 7/10,api/client.ts 7/13;之后无变更。v0.6 P1–P5 计划未推进。

### 1.2 用户原话

- 「后端更新了很多代码 但是前端一点没变化」
- 「除了智能助手没有什么绝对不能动的东西」
- 「页面设计可以改成鸿蒙风格」

### 6.2 LangGraph SSE 升级(解析层 + 类型层)

**后端事件 schema**(已升级,本版消费):
LangGraph 路径下产生 10 类事件(其中 3 类为 LangGraph 独有 — `handoff` / `memory_injected` / `truncation_decision`;7 类为 react_loop 兼容 — 名称与 react_loop schema 对齐):
| event 名 | payload 关键字段 | 含义 | 类别 |
|---|---|---|---|
| `llm_start` | `node: 'policy' \| 'memory' \| ...` | LLM 调用开始 | react_loop 兼容 |
| `llm_token` | `delta: string` | 流式 token | react_loop 兼容 |
| `tool_call` | `name, args` | 工具调用 | react_loop 兼容 |
| `tool_result` | `name, result, latency_ms` | 工具结果 | react_loop 兼容 |
| `handoff` | `from_agent, to_agent, task_summary` | specialist 切换 | **LangGraph 独有** |
| `memory_injected` | `count, source: 'L1' \| 'L2'` | 记忆注入 | **LangGraph 独有** |
| `truncation_decision` | `strategy, saved_tokens` | 压缩决策 | **LangGraph 独有** |
| `max_iterations_reached` | `{ iterations }` | 截断退出 | react_loop 兼容 |
| `turn_complete` | `final_message` | 本轮结束 | react_loop 兼容 |
| `llm_error` | `kind, message` | LLM 错误 | react_loop 兼容 |

**前端改造:**
- `src/api/client.ts` 中 `parseSSE` **保留旧 react_loop schema 解析**(LANGGRAPH_ENABLED=false 路径),**新增 LangGraph schema 分支**(根据 `VITE_LANGGRAPH_ENABLED` 启动时决定)
- `src/types/v0.4.ts` 中 `AgentEvent` 联合类型扩展,加 7 个新事件 variant
- `AgentWorkspace` 内 SSE consumer (`useAgentStream` hook,本版新建)按事件类型 dispatch 到 React state:
  - `llm_token` → 当前 assistant message 累积
  - `tool_call` / `tool_result` → 工具卡片新增/更新
  - `handoff` → TimelineRail 追加
  - `truncation_decision` → ReasoningTrace 顶部徽章
  - `memory_injected` → MemorySnapshotChip 更新计数
  - `turn_complete` → 流结束,刷新会话摘要

**LANGGRAPH_ENABLED 灰度开关:**
- `Settings.langgraph_enabled`(后端已有)→ 前端 `import.meta.env.VITE_LANGGRAPH_ENABLED` 同步,默认 `false`
- dev 模式顶部栏加"LangGraph 模式"开关,切换后 SSE 解析走对应分支(仅 dev,生产隐藏)
- 不破坏现有 react_loop 路径 — 旧测试套件(`SSEBridge byte test`)继续过

**兼容测试:**
- `src/api/client.test.ts` 加 LangGraph 事件解析 unit test(10 类事件各 1 case:含 3 类 LangGraph 独有 + 7 类 react_loop 兼容)
- `tests/e2e/agent-langgraph.spec.ts` Playwright e2e(本版新建):开启 LangGraph → 发消息 → 验证 10 类事件都流到 UI

### 6.3 Replay API(消息操作菜单)

**后端契约**(已存在,本版消费):
- `POST /api/agent/sessions/{sid}/replay/{msg_id}` — body `{}`,SSE 流回放断点续跑
- 返回与正常消息相同的 SSE schema(react_loop / LangGraph 兼容)
- 错误码:`404 msg_not_at_checkpoint` / `409 session_busy`

**前端集成:**
- 触发点:`ChatMessage` 的操作菜单(kebab icon,右上),**仅断点续跑消息**显示"重放"项
- 断点判断:后端 `AgentSessionDetail` 返回字段 `last_checkpoint_message_id`(本版新增字段),前端缓存该 ID
- 流程:
  1. 用户点"重放" → 弹确认 toast「将重放消息 #xxx 后的所有推理,确认?」
  2. 确认 → 调 `api.replayAgentMessage(sessionId, msgId)` → SSE 流
  3. SSE 流通过现有 `useAgentStream` hook 复用,事件入 React state
  4. 流结束 → TimelineRail 追加新条目,toast 提示"重放完成,新增 N 条推理"

**UI 细节:**
- 重放中的消息显示 ⏳ icon + 进度条
- 重放完成后消息底部加 🔁 徽章 + hover 显示重放时间
- 错误(404/409)→ toast `notFound`/`busy`,按钮置灰
- 批量操作:多选消息 → 工具栏显示"批量重放"(本版不实现,留作后续)

**文件:**
- 修改 `src/components/agent/ChatMessage.tsx` — 加 kebab 菜单 + 重放按钮
- 新建 `src/components/agent/MessageActions.tsx` — 抽出操作菜单组件
- 修改 `src/api/client.ts` — 加 `replayAgentMessage` 方法
- 修改 `src/types/v0.4.ts` — 加 `last_checkpoint_message_id` 字段到 `AgentSessionDetail`

### 8.4 React Query hooks 模式

每个 API 模块导出 query/mutation hooks:

```ts
// agent.ts
export function useAgentSession(id: string) {
  return useQuery({
    queryKey: ['agent', 'session', id],
    queryFn: () => api.getAgentSession(id),
    staleTime: 5_000,
  });
}

export function useHandoffTimeline(sessionId: string) {
  return useQuery({
    queryKey: ['agent', 'handoff', sessionId],
    queryFn: () => api.listHandoffs(sessionId),
    refetchOnWindowFocus: false,
  });
}

export function useReplayAgentMessage(sessionId: string) {
  return useMutation({
    mutationFn: (msgId: string) => api.replayAgentMessage(sessionId, msgId),
    onSuccess: () => queryClient.invalidateQueries(['agent', 'handoff', sessionId]),
  });
}
```

### 8.5 SSE 流复用模式

`useAgentStream(sessionId)` hook(本版新建)统一管理:

- 错误重试(最多 1 次)

## 12. 架构决策记录(ADR)

### ADR-001:视觉系统从 v0.6 Teal+Orange 切到鸿蒙 HarmonyOS

**决策:** 设计令牌 `src/lib/tokens.ts` 整体替换;Tailwind config extend 同步;15 公共组件 + 6 流程组件 + 24 页面颜色类名全量迁移。

**动机:** 用户原话"页面设计可以改成鸿蒙风格",且选择了"全套视觉+IA 重设计(重)"。Teal+Orange 配色与新 IA(抽屉式 + 服务卡片)视觉语言不契合。

**取舍:**
- ✅ 全站视觉一致,真正"重设计"而非补丁
- ❌ v0.6 P0 投入的 62 单测需重写颜色相关断言(估 4-6h)
- ❌ 视觉回归无 baseline(本版不引入 chromatic,留后续)

**回退成本:** `git revert` 单 commit(设计令牌替换)+ 单 commit(组件迁移),回退时间 < 1h。

### ADR-002:IA 从 9 主菜单压到 6 类目 + 服务卡片网格 + redirect 软着陆

**决策:** 6 类目抽屉导航,每个类目首页 HarmonyOS 服务卡片网格,19 旧 URL 显式 `<Navigate replace>` 兼容。

**动机:** 用户原话"除了智能助手没有什么绝对不能动",选了 A+B 混合方案。

**取舍:**
- ✅ 视觉语言扁平、清晰,符合鸿蒙抽屉范式
- ✅ redirect 软着陆保留旧路径,用户习惯不破坏
- ❌ 旧 URL 重定向增加心智负担(用户截图分享仍指向旧路径)
- ❌ 二级菜单深度 +1,部分功能可达性变差

**回退成本:** 路由表 revert + 旧 19 URL 恢复,回退时间 < 2h。

### ADR-003:LangGraph SSE 升级走前端灰度,默认 react_loop 路径不变

**动机:** 后端 LangGraph 已灰度(`Settings.langgraph_enabled` 默认 false),前端须保持兼容,等后端 KPI 达标后再统一切换。

- ✅ dev 模式可验证 LangGraph schema,提前发现问题
- ❌ 双分支代码维护成本(parseSSE 复杂度 +30%)

**回退成本:** `VITE_LANGGRAPH_ENABLED=false` 编译即可,无代码回退。

### ADR-005:故障注入 dev-only 隔离

**决策:** `/settings/dev-tools` 路由仅 `import.meta.env.DEV` 可见,生产构建 bundle 不含该路由文件。

**动机:** 后端 FaultInjector 是 dev/test 工具,不能进入生产。

**取舍:**
- ✅ 生产安全,误开风险归零
- ❌ 团队成员需要切到 dev 模式才能用

**回退成本:** 不适用。

---

### ADR-006:API 客户端分文件,不再单文件

**决策:** `src/api/client.ts` 拆为 `client.ts`(底层) + 按域分文件(`agent.ts`/`cost.ts`/...),每个域独立 React Query hooks。

**动机:** 10 项新功能接入,单文件 client.ts 已超 400 行,可读性下降。

**取舍:**
- ✅ 单一职责,每个文件 < 200 行
- ✅ 测试 mock 范围缩小
- ❌ import 路径变多,需维护 `api/index.ts` barrel

**回退成本:** 单文件还原,回退时间 ~1h。

---

### ADR-007:本月度成本 dashboard 独立页,不放仪表盘

**决策:** `/cost` 独立路由,抽屉导航"监测"类目下,不混入仪表盘。

**动机:** 成本数据体量大(多维聚合 + 趋势图),混进仪表盘会拖慢首屏;独立页利于分享和打印。

**取舍:**
- ✅ 首屏不受影响,深度链接友好
- ❌ 用户需多一次点击

**回退成本:** 路由挪回仪表盘,~30min。
