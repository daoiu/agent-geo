## §2 已确定决策（重新进 brainstorm 会拖慢流程，请尊重这些）

业务：知识库按"品牌"组织（北北云吞 / 蓝天钢管 / 陈妹螺蛳粉 等）。
用户可能：
- 提到品牌 → LLM 应该能从 list 找 kb_id
- 忘了品牌 → LLM 应该自动列全部
- 模糊问题 → LLM 应该跨库搜

设计 三件套（已 brainstorm，用户选 ② + 修改）:

1. **新增 `list_knowledge_bases` 工具**（no args）→ `[kb_id, kb_name, doc_count, created_at]`
2. **`search_knowledge` 改 `kb_id` 可选** — 不传走跨库 hybrid，传走单库 hybrid
3. **多篇文章生成走 `create_generation_task`** — 落 v0.2 tasks 表，agent turn 立即结束；用户在 `/tasks/<id>` 审核。**不在 agent 会话里循环。**
4. 已有工具（`diagnose_brand` / `generate_article`）**不动**
5. `MAX_REACT_ITERATIONS 5 → 7`
6. `AGENT_SYSTEM_PROMPT` 追加"知识库使用策略" 10 行段

## §5 项目惯例

### §5.1 Commit 格式

项目风格（最近 6 个 commit 为例）:
```
fix(backend/v0.5): ...
feat(backend/v0.4): ...
feat(frontend/v0.6/P1.2): ...
docs(v0.6/P1.3): ...
```

适用规则：
- **scope** 必填：`backend` / `frontend` / `docs` / `<层>-<版本>`
- **desc** 中文，~30-60 字
- 一个 task 一个 commit（不要再 squash — 用户要分立的 git log）

### §5.2 测试要求

- TDD 严格执行：先写失败测试 → 跑看 fail → 最小实现 → 跑看 pass
- 单文件 ≥ 70% 覆盖（项目惯例）
- 既有测试零回归 — 改 `TOOLS` 列表 / schema 时同步更新断言

### §5.3 错误处理 / 边界

- 未知工具 → `ValueError`
- LLM 缺参 → pydantic 抛 `ValidationError`，executor 不接
- KB 不存在 → repo 层返 None，executor 透 ValueError
- `MAX_REACT_ITERATIONS` 撞限 → `max_iterations_reached` SSE 事件
- `HumanConfirmationRequired` → 写类工具抛之，agent 循环暂停

## §6 实施准则

1. **每个 task 走完才进下一个**：5 步流程（写测试 → 跑看 fail → 最小实现 → 跑看 pass → commit）必须 intact。
2. **不要叠 commit**：1 task = 1 commit。改坏先 git reset 上一 commit。
3. **既有测试零回归**：每 task 完成后立即跑 `pytest -q tests/` 验证全集。
4. **plan 是真理**：以 `docs/superpowers/plans/2026-07-11-geo-agent-kb-fullchain-plan.md` 为准，spec 是背景。**所有代码片段已列在 plan 里 — 直接复制粘贴运行即可**。
5. **不要顺手重写其他文件**：plan 没说改的不动。即便是 v0.4 老代码看着别扭。
6. **绝对不要 commit 直到我说 "commit"** — 项目惯例（用户确认制）。
7. **代码补全 / 静态类型**：所有新代码过 `npx tsc --noEmit` (前端) 和 `python -m py_compile` (后端) 通过。
8. **执行 skill 流程**：

## §8 不要踩的坑

1. **N+1 已记 diff 风险**：Task 1 的 `doc_count` 必须**单 SQL** JOIN GROUP BY，**不要**遍历 KB 时逐个 `count(documents)`。已有测试 `test_list_kbs_doc_count_n_plus_one_safe` 用 SQLAlchemy event 探针自动检测。
2. **路由顺序**：本 PR 不动 API 路由（spec §7 明确）。
3. **`generate_article` 别碰**：它走 `HumanConfirmationRequired`；`create_generation_task` 是新工具，与之并存。两者职责清晰，不要合二为一。
4. **prompt 措辞**：spec §6 给了具体文本，不要自己重写。如果觉得措辞不准确，回 user 而不是默默改。
5. **`create_generation_task` 误向 HumanConfirmation**：spec 明确"**不**询问确认，直接落 v0.2 tasks 表"。`test_create_generation_task_happy_path` 显式断言不抛 `HumanConfirmationRequired`。
6. **LF/CRLF**：项目 Windows 仓库；git 提交会报 LF→CRLF warning，无影响。
7. **未跟踪文件**：若看到 `backend/app/domain/security/ssrf.py` 与 `tests/test_ssrf_validator.py`（来自别的会话），**不要碰**。
8. **不要动 P1.3 已 commit 的代码**（search_across_kbs / search_chunks_all_keywords / KnowledgeRepository.search_chunks_hybrid / Chroma VectorIndex）— 它们是 Task 1-4 的依赖，本 P1.4 只是 *使用* 之。
